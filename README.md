# 分割CSVのダウンロード

MONOQLO PTランキングの対局記録(monoqlo-data の `YYYYMM.csv`)を10対局ずつに分けたCSVと、チーム戦の対局記録(event-data の `-gamesN.csv`)を開催日ごとに分けたCSV、それを一覧からダウンロードするページを置くリポジトリ。
牌譜の成績を書き出す拡張機能の「対局一覧のCSVを読み込む」で、少しずつ・手分けして取得するために使う。

ページ: https://monoqlo-league.github.io/splitdata-download/

## ページの使い方

1. 取得したいファイルの行で、名前を入れる。名前は行ごとに入れる(ほかの行には入らない)。一度使った名前は、入力欄の候補に出る。
2. 「ダウンロード」を押す。名前・ファイル名・日時が記録され、CSVが保存される。
3. 記録は「取得した人」の列に出る。ほかの人が開いたページにも出る。

- すでに誰かが取得したファイルは、押すと確認が出る。もう一度押すと、自分の名前も記録して取得する。
- 同じ人が同じファイルを取り直しても、記録は増えない。
- 押すとすぐにダウンロードが始まり、記録は裏で送る。記録先が混んでいると、記録には数十秒かかることがある。
- 記録に失敗したら、自動で2回まで送り直す。それでもだめなら、その行に「記録を送り直す」が出るので、少し待って押す(ダウンロードはやり直さない)。
- 記録を送っている途中や、記録できていない行があるときにページを閉じようとすると、確認が出る。
- ページの一番上に「DL協力者ランキング」が出る。取得したファイルの数(同じ人が同じファイルを取り直した分は数えない)が多い順に3位まで。ファイル数が同じなら対局数の多い順で、両方同じなら同じ順位になる。

## 中身

| ファイル | 役割 |
|---|---|
| `YYYYMM/YYYYMM-連番.csv` | 個人戦の分割したCSV。1ファイル10対局。開始時間の古い順(202608 までは月の最後だけ端数) |
| `event/大会/大会-gamesN-開催日.csv` | チーム戦の開催日ごとのCSV(例: `event/20260901/20260901-games2-20261014.csv`)。同じフォルダの `info.json` は、ページに出す大会名とリーグ名 |
| `index.html` | 一覧とダウンロードのページ |
| `upload.html` | ゲームデータのアップロードページ(管理者用・GitHubでログイン) |
| `gas/Login.gs` | 「GitHubでログイン」の仲立ちスクリプト(Google Apps Script に貼る) |
| `files.json` | ページが読むファイルの一覧。`tools/build-manifest.js` が作る |
| `tools/split-new.py` | 対局記録から、まだ入っていない対局を10対局ずつ分割する(自動で動く) |
| `tools/split-event.py` | チーム戦の対局記録から、対局がそろった開催日の分を1ファイルにする(自動で動く) |
| `.github/workflows/split.yml` | 分割を自動で動かす仕組み |
| `config.js` | 記録先のURLを書くところ |
| `gas/Code.gs` | 記録先(Googleスプレッドシート)に貼るスクリプト |
| `downloads/majsoul-paifu-list.zip` | ページの「拡張機能をダウンロード(ZIP)」で配る拡張機能(雀魂 牌譜スタッツ出力 リスト取得版) |
| `downloads/majsoul-paifu-list-manual.pdf` | ページの「使い方マニュアル(PDF)」で開くマニュアル |

202511〜202608 は手作業で分割した(10か月、2,618対局、266ファイル)。
202509・202510 は集計CSV(`-summary.csv`)が monoqlo-data にあるので入れていない。202609 は対象外。
202610 からは、次の「自動の分割」で足していく。

## 自動の分割

monoqlo-data に対局記録(`YYYYMM.csv`)がアップロードされると、数分以内に分割CSVが足され、ページに出る。

- まだどの分割CSVにも入っていない対局(牌譜リンクで見る)だけを、開始時間の古い順に10対局ずつ切り出し、続きの連番で足す。
- すでにある分割CSVは書き換えない。同じ対局記録を何度アップロードしても、同じ対局が重なって入ることはない。
- 10対局に満たない残りは出さない。次のアップロードで10対局に達したら出す。そのため、月の最後の端数(10対局未満)は自動では出ない。
- 非表示状態が `no` でない対局は入れない。
- 対象は 202610 以降の月。変えるときは `tools/split-new.py` の `FROM_MONTH` を書き換える。
- チーム戦の対局は入れない。event-data の対局記録(`*-gamesN.csv`)にある対局は飛ばす。
- 月のCSVから、すでに分割した対局が10対局以上なくなっていたら、その月は分割しない。チーム戦の対局記録や別の月のCSVを誤って上げたときの備え。正しいCSVで上書きされれば、次の分割から元どおり動く。知らせは monoqlo-data 側の点検が Discord に送る。

アップロード直後に動くのは、monoqlo-data の Secret `SPLIT_DISPATCH_TOKEN` が設定されているとき(設定は monoqlo-data の README)。
無いときや届かなかったときも、毎日4時ごろ(日本時間)に自分で確かめて分割する。今すぐ動かすときは「Actions」タブ →「分割CSVを足す」→「Run workflow」。

月の最後の端数を出したいときは、手で `YYYYMM/YYYYMM-連番.csv` を足し(形式は既存のファイルと同じ)、下の「CSVを足したり入れ替えたりしたとき」のとおり `files.json` も作り直す。
入れた対局は二度と自動では出ないので、あとから同じ月の対局が増えても重ならない。

誤って分割CSVができてしまったときは、そのファイルを消し、後ろのファイルの番号を詰めて、`files.json` を作り直す。
番号は、月のCSVを開始時間の古い順に10対局ずつ数えた位置と一致させる(monoqlo-data の点検の知らせに出る番号と同じ)。
消したファイル・付け替えたファイルの取得記録はスプレッドシートに残る。付け替えた番号の記録は、新しいファイルの取得として数えられるので、必要ならスプレッドシートで直す。
(2026-10-16: チーム戦の対局記録が `202610.csv` として上がり、202610-33〜41 にチーム戦の対局が入った。消して、42→33、43→34 に付け替えた)

## チーム戦の開催日ごとのCSV

ページでは「チーム戦」として、大会ごとに個人戦の上に出る。

- event-data のスケジュール(`-schedule.csv`)と対局記録(`-gamesN.csv`)を付き合わせ、**その日の対局がすべてそろった開催日**の分を1ファイルにする。そろうまでは出さない。
- その日の対局数は、スケジュールの「その日に使う卓 × 卓ごとの試合数」。gamesN は、スケジュールに出てくる N番目のリーグ。
- 開催日は開始時間の日付。朝6時より前に始まった対局は前の日に数える。スケジュールにない日の対局(延期など)は、直近の前の開催日に数える。
- その日の対局がすべて event-data の詳細成績のもと(`summary/…-gamesN-summary.csv`)に入っていれば、出さない(取る必要がないため)。1対局でも足りなければ、その日の全対局を出す。
- 一度出したファイルは書き換えない。非表示状態が `no` でない対局は入れない。
- event-data に対局記録が上がると、そちらのワークフローがこのリポジトリに知らせる(event-data の Secret `SPLIT_DISPATCH_TOKEN`)。無いときも、毎日4時ごろの確認で出る。

**記録先のスクリプトを新しくする必要がある。** チーム戦のファイル名を記録できるように `gas/Code.gs` の `FILE_PATTERN` を広げた。スプレッドシートの Apps Script に貼り替え、下の「スクリプトを直したとき」のとおり新バージョンでデプロイする。貼り替えるまでは、チーム戦のファイルはダウンロードできるが、取得の記録が残らない(行に「記録を送り直す」が出る)。

## 記録の仕組み

GitHub Pages は置いてあるファイルを見せるだけで、入力を保存できない。そのため、記録は Googleスプレッドシートに残す。
ページは、スプレッドシートに付けたスクリプト(ウェブアプリ)に名前とファイル名を送り、開くたびに記録を読み込んで表示する。

### 最初の設定(1回だけ)

1. Googleスプレッドシートを新しく作る。名前は何でもよい(例:「分割CSV DL記録」)。
2. メニューの **「拡張機能」→「Apps Script」** を開く。
3. 最初から入っているコードをすべて消し、このリポジトリの `gas/Code.gs` の中身を貼って、保存する。
4. 右上の **「デプロイ」→「新しいデプロイ」** を押す。
   - 「種類の選択」の歯車から **「ウェブアプリ」** を選ぶ。
   - 「次のユーザーとして実行」は **「自分」**。
   - 「アクセスできるユーザー」は **「全員」**。(「Googleアカウントを持つ全員」ではない)
   - 「デプロイ」を押す。初回はアクセスの承認を求められるので、自分のアカウントで許可する。
   - 承認の途中で「Google hasn’t verified this app(このアプリは Google で確認されていません)」と出る。自分で貼ったスクリプトには必ず出る表示。左下の「Advanced(詳細)」→「Go to …(unsafe)(…に移動)」→「Allow(許可)」と進む。
5. 表示された **「ウェブアプリのURL」**(`https://script.google.com/macros/s/…/exec`)をコピーする。
6. このリポジトリの `config.js` を開き、`endpoint: ""` の `""` の中にURLを貼って、コミットする。

1〜2分後にページを再読み込みすると、上の「記録先がまだ設定されていない」の表示が消える。
最初のダウンロードで、スプレッドシートに「DL記録」というシートができ、日時・ファイル・名前が1行ずつ入っていく。

### 記録を直す・消す

スプレッドシートの「DL記録」の行を、直接書き換えるか削除する。ページは次に読み込んだときに、その内容を表示する。

### スクリプトを直したとき

`gas/Code.gs` を貼り替えただけでは反映されない。**「デプロイ」→「デプロイを管理」→ 鉛筆 →「バージョン」を「新バージョン」にして「デプロイ」** する。URLは変わらない。

## 拡張機能やマニュアルを新しくしたとき

`downloads/` の同じ名前のファイルを、新しいもので上書きしてコミットする。ページのボタンとリンクは、そのまま新しいファイルを指す。

拡張機能のZIPを新しくしたときは、`index.html` の次の3か所も書き換える。

- 説明文にある版の番号(`v1.0.0`)
- 「この拡張機能の安全性について」にある、ZIPを作ったコミット(ソースのリポジトリ `majsoul-paifu-list` のコミット)
- 同じ欄にあるZIPの指紋(SHA-256)。`sha256sum downloads/majsoul-paifu-list.zip` などで出す

ZIPは、ソースのリポジトリのコミットから `git archive --format=zip --prefix=majsoul-paifu-list/ -o majsoul-paifu-list.zip <コミット>` で作る。

## CSVを足したり入れ替えたりしたとき

リポジトリの直下で次を実行し、できた `files.json` もCSVと一緒にコミットする。

```
node tools/build-manifest.js
```

## 注意

- 名前は自己申告。入力されたとおりに記録され、ページを開いた人全員に表示される。
- このリポジトリは公開なので、ページを通さずにGitHubから直接ファイルを取ることもできる。その場合は記録されない。
- 記録先のURLはページから見えるので、いたずらの書き込みは防げない。おかしな行は、スプレッドシートで消す。

## ゲームデータのアップロード(管理者用)

ページ: https://monoqlo-league.github.io/splitdata-download/upload.html (一覧のページからはリンクしていない)

雀魂から書き出した対局記録(牌譜履歴)と、拡張機能が出力した詳細成績(`-summary.csv`)を、個人戦(monoqlo-data)・チーム戦(event-data)どちらにも上げられる。ファイルは「ファイルを選ぶ」でも、画面への放り込みでも入れられ、何個でもまとめて入れてよい。

- 最初に「GitHubでログイン」を押す。GitHub のログインと許可の画面から戻ると使える。上げられるのは monoqlo-data と event-data に書き込める GitHub アカウントだけで、コミットはログインした人の名前で残る。ログインは8時間ほどで切れる(切れたらもう一度押す)。トークンやパスワードの入力は無い。
- ログインしたら、**「2. 個人戦かチーム戦か」を選ぶ**(最初はどちらも選ばれていない。選ぶまでファイルは入れられない)。チーム戦は大会も選ぶ(いちばん新しい大会が初め)。途中で替えると、入れていたファイルは取り消す。
- **対局記録**は、雀魂が書き出したファイルを名前を変えずに入れてよい。
  - 個人戦: 対局の月(開始時間のいちばん多い月)の `YYYYMM.csv` として、中身は変えずに上げる。月は画面で替えられる。
  - チーム戦: 雀魂の書き出しには予選・セミファイナル・ファイナルの対局がまとめて入っているので、1対局ずつリーグを決めて `YYYYMMXX-gamesN.csv` に分ける(行はそのまま振り分け、書き換えない)。
    - 置いてある `-gamesN.csv` にある対局は、そのリーグ。
    - 新しい対局は、開始時間の古い順に、スケジュールの対局数にまだ届いていないいちばん前のリーグへ入れ、届いたら次のリーグへ。対局数の決まっていない(スケジュールが無い・未定の)リーグには残りを全部入れる。非表示の対局は、その時点のリーグに入れる(数えない)。
    - 大会の開始日(スケジュールのいちばん早い開始日)より前の対局は入れない。
    - 中身が置いてある版と同じリーグ(終わったリーグなど)は上げない。
  - 置いてある版にあった対局が無くなるときは、止めて知らせる(「それでも上げる」に印を付けたときだけ上げる)。
  - **取り違えの守り**: 選んだ種類と逆の置き場にある対局(個人戦を選んだのに event-data の対局、チーム戦を選んだのに monoqlo-data の対局や別の大会の対局)が入っていたら上げない(印も付けられない)。
- **詳細成績**は、ゲームIDで、選んだ種類の対局記録と照らし、その対局が入っている月・リーグの `summary/…-summary.csv` に合体する(ファイル名は見ない)。分割したサマリーを何個入れてもよい。
  - すでにある対局は重ねない。中身が違う同じ対局は、置いてある方を残して知らせる。どの対局記録にも無い対局は使わない(先に対局記録を上げると入る)。
  - 置いてある行の並びはそのままにして、足す対局を後ろに足す。BOM 付き・改行 CRLF。
  - 4人そろっていない対局・列の数が合わない行があるファイルは上げない。和了数・立直数の内訳の食い違い、内部IDが空の行(回線切れのCPU)は知らせるだけ。
- 入れたファイルは、欄の右上の ✕ で1件ずつ取り消せる(下の「取り消す」は全部まとめて)。
- 上げるときは、置き場の最新の版を読み直してから、リポジトリごとに1つのコミットにまとめる。各リポジトリの自動処理(一覧の作り直し・点検・Discord への通知・分割CSVの追加)はいつもどおり動く。上げたあとの「上げた」は、個人戦ならランキング、チーム戦ならチーム戦ランキングのページを開く。

### 「GitHubでログイン」の設定(1回だけ)

ログインには GitHub App を1つ使う。書き込めるのは、その App を入れたリポジトリ(monoqlo-data・event-data)だけで、しかもログインした人に書き込み権限があるときだけ。

1. **GitHub App を作る。** GitHub の monoqlo-league の Organization の「Settings」→ 左下「Developer settings」→「GitHub Apps」→「New GitHub App」。
   - GitHub App name: 何でもよい(例: `monoqlo-upload`)
   - Homepage URL: `https://monoqlo-league.github.io/splitdata-download/`
   - Callback URL: `https://monoqlo-league.github.io/splitdata-download/upload.html`
   - 「Expire user authorization tokens」は印を付けたまま。「Request user authorization (OAuth) during installation」は付けない。
   - Webhook の「Active」は印を外す。
   - Permissions → Repository permissions → **Contents を Read and write**(ほかは No access のまま)。
   - Where can this GitHub App be installed: **Only on this account**。
   - 「Create GitHub App」を押す。
2. できた App のページで、**Client ID** を控える。「Generate a new client secret」を押して出た **Client secret** も控える(1回しか出ない)。
3. 左の「Install App」→ monoqlo-league の「Install」→「Only select repositories」で **monoqlo-data** と **event-data** を選んで入れる。
4. https://script.google.com で「新しいプロジェクト」を作り、`gas/Login.gs` の中身を貼って保存する。「プロジェクトの設定」→「スクリプト プロパティ」に `CLIENT_ID`(2. の Client ID)と `CLIENT_SECRET`(2. の Client secret)を足す。
5. 「デプロイ」→「新しいデプロイ」→「ウェブアプリ」。実行するユーザーは**自分**、アクセスできるユーザーは**全員**で公開する。
6. このリポジトリの `config.js` の `githubClientId` に 2. の Client ID、`loginEndpoint` に 5. の URL を貼ってコミットする。

Client secret を替えるときは、App のページで作り直し、4. のスクリプト プロパティを書き換える。
